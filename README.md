## Установка сервера WireGuard
Это краткая инструкция, по ручной установке на Ubuntu 20.04. Логинимся на сервер по ssh под рутом, пробрасываем публичный ключ, запрещаем парольное соединение, рестартуем ssh-сервер. Далее по сабжу.  
Обновляем репозиторий программ на сервере:  
`apt update && apt upgrade -y`  
Ставим wireguard:  
```
apt install -y wireguard
apt install resolvconf iptables ufw -y
```  
Генерим ключи сервера:  
`wg genkey | tee /etc/wireguard/privatekey | wg pubkey | tee /etc/wireguard/publickey`  
Находим сетевой интерфейс типа ens3, выполняем команду:  
`ip a`  
Настраиваем IPv4 форвардинг:  
`echo "net.ipv4.ip_forward=1" >> /etc/sysctl.conf`  
Если на машине стоит nginx обязательно также вносим:  
`echo "net.ipv4.ip_nonlocal_bind = 1" >> /etc/sysctl.conf`  
Аналогично в том же файле конфиг для IPv6, если требуется.  
Применяем параметры ядра для применения IPv4, IPv6 маршрутизации:  
`sysctl -p`  
Настраиваем виртуальный интерфейс wg0. Редактируем vim /etc/wireguard/wg0.conf  
```
[Interface]
PrivateKey = <privatekey>
Address = 192.168.11.1/24
ListenPort = 51810
PostUp = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o ens3 -j MASQUERADE
```

`ListenPort` - задаем upd-порт на котором будет крутиться наш сервер, он д.б. открыт  
`eth0` - вышеописанный адаптер / сетевой интерфейс  

Команды для запуска, остановки, и пр. WG-сервера/сервиса
```
systemctl enable wg-quick@wg0.service
systemctl start wg-quick@wg0.service
systemctl stop wg-quick@wg0.service
systemctl restart wg-quick@wg0.service
systemctl status wg-quick@wg0.service
```

Как указывалось выше, требуется проверять настройки правил для FireWall, для современных Unix-систем чаще всего используется встроенная утилита iptables  

Необходимо добавить правило FireWall для нового виртуального адаптера. Проблема описана на stackoverflow. Добавляем правило:  
`iptables -A FORWARD -i wg0 -o wg0 -j ACCEPT`  

Для применения правил сетевого экрана может потребоваться перезапустить VPN-сервис / виртуальный адаптер, или само ядро системы, т.е.  
`reboot now`  

## Подготовка конфига для клиента WireGuard  

Актуальное:  
Тащим на сервер в директорию `/etc/wireguard/`  скрипт `client-add.sh` .  
Создаем каталог `/etc/wireguard/client`  
Задаем конфиги в начале скрипта.  
Юзаем скрипт.  

Устаревшее, или для тех кто любит рутину:
Генерируем ключи для клиента аналогично генерации ключей для сервера. Далее готовим конфиг и передаем его на сторону клиента. Шаблон для конфига клиента выглядит так:
```
[Interface]
PrivateKey = <CLIENT-PRIVATE-KEY>
Address = 10.0.0.2/32
DNS = 8.8.8.8

[Peer]
PublicKey = <SERVER-PUBKEY>
Endpoint = <SERVER-IP>:51830
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 20
```

Address – задаем IP-адрес клиента в нашей виртуальной частной сети. Применяется нотация CIDR  
DNS – обязательный параметр, 8.8.8.8 – IP-адрес Гугла.  

Для настройки когда в нашей частной приватной сети:
клиенты видят друг друга по внутренним адресам  
`PersistentKeepalive = 30`  
клиенты ходят в интернет каждый через свой интернет (провайдера)  
`AllowedIPs = 192.168.11.0/24 # address-pull of VirtualPrivateNetwork`  

Для настройки когда внешний IP-адрес клиента передается как весь интернет-трафик  
`AllowedIPs = 0.0.0.0/0`

## FireWall он же Брандмауэр
Для проверки корректности настройки Частной Приватной Сети требуется выполнить ping с одного клиента на другой. Для Windows (возможно перенести в открытую инструкцию) правила открытия ICMP порта для диапазона находятся:  
- **Панель управления\Система и безопасность\Брандмауэр Защитника Windows**  
- **Дополнительные Параметры**  
    - **Входящие подключения: Сортировка по протоколу ICMPv4 -> Включить Правило**  
    - **Исходящие подключения: Сортировка по протоколу ICMPv4 -> Включить Правило**  

## Тюнинг Linux-сервера
Для увеличения пропускной способности сервера необходимо увеличить дефолтные настройки для `{rmem,wmem}` и `{mtu}`  

`{rmem, wmem}` (по гиду https://www.cyberciti.biz/faq/linux-tcp-tuning/)  
Добавляем / изменяем значение конфигурационного файла  /etc/sysctl.conf и рестартуем сервис, можно дополнительно ребутнуть тачку  
```
echo 'net.core.wmem_max=12582912' >> /etc/sysctl.conf
echo 'net.core.rmem_max=12582912' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_rmem= 10240 87380 12582912' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_wmem= 10240 87380 12582912' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_window_scaling = 1' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_timestamps = 1' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_sack = 1' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_no_metrics_save = 1' >> /etc/sysctl.conf
echo 'net.core.netdev_max_backlog = 5000' >> /etc/sysctl.conf

sysctl -p
```

{mtu = Maximum Transmission Unit}
Смотрим интерфейс и его значение mtu:
`ip a`  

Определяем / рассчитываем оптимальное значение для mtu. Например задаем размер пакета 1350 и гоняем пинг до тех пор пока не потребуется фрагментация пакета (Packet needs to be fragmented but DF set.).   
`ping 192.168.11.3 -f -l 1350 -n 15`  
На одном из стендов в тестах на 1350 пошли потери loss. При 1300 потерь не было.   
Чтобы задать временное значение `mtu`, которое сбрасывается при перезагрузке машины:   
	`ip link set mtu 1200 eth0`  
Задать постоянное значение можно в конфиг. файле таком-то прописав конфиг:  
	- `такой конфиг`  

На данный момент принято решение не мешать автоподстройке размера mtu и пользоваться стандартным размером. Однако, для особых случаев размер может быть изменен.  
## Добавление клиента
Процесс добавления клиента включает в себя: выделение ip-адреса в диапазоне частной приватной сети, генерация ключей для клиента, формирование конфига для клиента, добавление записей в конфиг сервера,  рестарт сервера. Выполнение работ “руками” энергозатратно и может приводить к ошибкам исполнителя. Для добавления клиента может быть использован самописный, т.н. кастомный, скрипт `client-add.sh`  
Скрипт следует лучше всего разместить в директории  
`/etc/wireguard/`

Первоначально, разово следует создать директорию куда будут складываться конфиги клиента  
`mkdir /etc/wireguard/client/`  

При запуске скрипта в диалоговом окне потребуется ввести имя клиента и порядковый номер (число) в диапазоне частной приватной сети.  
Пример  
`Please Enter Client Name: Ivan`  
`Please Enter IP Address Number [2..255]: 33`  

После чего, будет создан конфиг указанного клиента `./client/Ivan.conf` и к конфигу сервера будет добавлена запись о клиенте с соответствующим ip-адресом `192.168.11.33` и ключами. Все что требуется – скачать конфиг клиента и применить его на целевой машине.

## QR-код для мобильных устройств  
каждый ключ для удобства считывания может быть предствлен графически в виде т.н. QR-кода 
- на сервере устанавливаем утилиту qren
```
apt install qrencode
```
- скармливаем ключ на вход утилите qren с параметрами:
```
qrencode -t ansiutf8 -r client/Ivanov.conf
```
